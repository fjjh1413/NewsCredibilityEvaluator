# 智闻辨真用户端设计系统

> 本文档是第四阶段用户端 Vue 前端的全局设计规范。后续开发首页、登录注册、新闻检测、检测结果、历史记录、高风险新闻展示、个人中心时，必须先遵守本文件，再参考页面级补充说明。

## 1. 设计来源

本设计系统基于 UI UX Pro Max 检索结果整理：

- 产品方向：AI 新闻可信度评估、RAG 证据检索、企业级安全风控平台。
- 推荐模式：Enterprise Gateway，强调可信入口、明确主行动、专业信任信号。
- 推荐风格：Minimalism & Swiss Style，强调网格、留白、清晰层级、高对比、克制装饰。
- 辅助风格：Data-Dense Dashboard、Executive Dashboard、Trust & Authority，用于结果页、历史表格和高风险展示。
- 技术栈约束：Vue3 + Vue Router + Pinia + Axios + Element Plus + ECharts。

最终风格定位：科技蓝白 + 安全风控平台 + 企业级 AI 平台。界面必须专业、现代、可信、清爽，适合课程设计答辩、毕业设计展示和项目截图。

## 2. 核心原则

1. 不使用默认 Element Plus 裸样式，必须通过项目级 class、CSS 变量和组件封装形成统一视觉。
2. 不使用普通后台模板风：用户端应像企业级 AI 产品，而不是廉价管理后台。
3. PC 端展示优先，兼顾 375px、768px、1024px、1440px 响应式。
4. 信息层级优先：先展示结论和关键评分，再展示原因、证据和过程。
5. 风险等级必须颜色、标签文案、图标和辅助说明共同表达，不能只靠颜色。
6. 动效克制，主要用于 hover、focus、loading、图表渐入，时长 150-300ms。
7. 图标统一使用 lucide 或 Element Plus Icons，不使用 emoji 作为 UI 图标。
8. 所有可点击元素必须有 hover、active、focus-visible 和 disabled 状态。

## 3. 颜色规范

### 3.1 品牌与基础色

| Token | 用途 | Hex |
|---|---|---|
| `--color-primary` | 主色、重点按钮、链接 | `#0369A1` |
| `--color-primary-strong` | 顶部导航、深色标题、重要强调 | `#0C4A6E` |
| `--color-primary-soft` | 浅色主背景、信息底色 | `#E0F2FE` |
| `--color-accent` | AI、检索、次级强调 | `#0EA5E9` |
| `--color-success` | 可信、通过、正向状态 | `#16A34A` |
| `--color-warning` | 存疑、需要核查 | `#F59E0B` |
| `--color-orange` | 疑似谣言、中高风险 | `#F97316` |
| `--color-danger` | 高风险谣言、危险操作 | `#DC2626` |
| `--color-bg-page` | 页面背景 | `#F5F9FC` |
| `--color-bg-panel` | 卡片/面板背景 | `#FFFFFF` |
| `--color-bg-subtle` | 弱分区背景 | `#F8FAFC` |
| `--color-text` | 正文主文本 | `#1E293B` |
| `--color-text-strong` | 标题、关键数字 | `#0F172A` |

| `--color-border` | 默认边框 | `#D8E3EE` |

### 3.2 使用规则

- 页面背景使用极浅蓝灰，不允许大面积纯白空洞。
- 卡片以白色为主，可使用 92%-96% 白色半透明，但必须保证浅色模式边框可见。
- 主色蓝占主导，绿色、黄色、橙色、红色只用于状态和风险，不做大面积装饰。
- 避免大面积紫蓝渐变、米黄色、深蓝整屏、棕橙系主题。
- 图表颜色优先使用蓝、绿、琥珀、橙、红，必须带数值标签或 tooltip。

## 4. 字体与字号

### 4.1 字体

中文项目优先采用现代无衬线字体：

```css
font-family: "Noto Sans SC", "Microsoft YaHei", "PingFang SC", "Helvetica Neue", Arial, sans-serif;
```

若后续允许引入 Web Font，可使用 UI UX Pro Max 推荐的 Noto Sans SC。不要使用新闻编辑类衬线字体作为主 UI 字体，因为本项目更偏企业级风控工具。

### 4.2 字号层级

| Token | 建议值 | 用途 |
|---|---:|---|
| `--font-size-xs` | 12px | 标签、表格辅助信息 |
| `--font-size-sm` | 13px | 表格、表单提示 |
| `--font-size-base` | 14px | 默认正文、表单 |
| `--font-size-md` | 16px | 卡片标题、重要正文 |
| `--font-size-lg` | 20px | 页面区块标题 |
| `--font-size-xl` | 24px | 页面标题 |
| `--font-size-score` | 48px | 结果页 final_score |

规则：

- 不使用视口宽度动态缩放字号。
- 字间距保持 0，不使用负字距。
- 表格和紧凑控件不使用过大标题，避免营销页气质。

## 5. 间距、圆角、阴影

### 5.1 间距

采用 8px 基准：

| Token | 值 | 用途 |
|---|---:|---|
| `--space-1` | 4px | 微间距 |
| `--space-2` | 8px | 标签、图标间距 |
| `--space-3` | 12px | 表格、紧凑控件 |
| `--space-4` | 16px | 卡片内距 |
| `--space-5` | 20px | 表单组间距 |
| `--space-6` | 24px | 普通区块 |
| `--space-8` | 32px | 页面主分区 |
| `--space-10` | 40px | 首屏大区块 |

PC 页面内容最大宽度建议 1180-1280px，结果页可到 1320px。页面左右安全边距：桌面 32px，平板 24px，手机 16px。

### 5.2 圆角

- 普通卡片：8px。
- 输入框、按钮、标签：6px。
- 大型结果面板：10px，不能超过 12px。
- 不做过度圆润的胶囊式后台模板，除非用于风险 tag。

### 5.3 阴影

```css
--shadow-card: 0 8px 24px rgba(15, 23, 42, 0.06);
--shadow-hover: 0 12px 30px rgba(15, 23, 42, 0.10);
--shadow-focus: 0 0 0 3px rgba(14, 165, 233, 0.18);
```

卡片阴影必须轻，主要依靠边框、背景和间距建立层次，不使用厚重悬浮效果。

## 6. 组件规范

### 6.1 按钮

- 主按钮：蓝底白字，用于“立即检测”“提交检测”“查看结果”。
- 次按钮：白底蓝字蓝边，用于“查看历史”“返回”“重置”。
- 危险按钮：红色，仅用于明确危险动作，不用于风险展示主按钮。
- 图标按钮：使用 32-36px 固定尺寸，图标 16-18px，必须有 tooltip 或 aria-label。
- loading 按钮必须保留原宽度，避免文字切换导致布局抖动。

### 6.2 表单

- 输入框高度 40px，正文 textarea 最小高度 220px。
- 标签在上，说明文本在下；不要把错误信息塞进 placeholder。
- 新闻检测页标题、正文为主输入，类别和来源为辅助输入。
- 使用 `.trim` 等 Vue v-model 修饰符处理基础输入；复杂校验后续可引入 VeeValidate 或 FormKit。
- 检测提交时显示按钮 loading 和页面局部 loading，不让界面静止。

### 6.3 表格

- 表头背景 `#F8FAFC`，表头文字 13px、600。
- 行高 48-56px，历史记录可 56px，管理类密集表格可 48px。
- 行 hover 使用浅蓝灰，不使用强烈色块。
- 风险等级列必须使用 RiskTag，不直接输出纯文本。
- 分页、筛选和搜索保持同一行，窄屏可折行。

### 6.4 卡片

- 卡片用于独立信息块，不允许卡片套卡片。
- 结果页关键指标卡、证据卡、风险点卡可使用统一边框和轻阴影。
- 卡片标题行包含图标、标题、必要操作；正文不堆叠无层级文字。
- 卡片内距桌面 20-24px，紧凑信息卡 16px。

### 6.5 标签

- 标签高度 24-28px，字号 12-13px。
- 关键词标签使用浅蓝底深蓝字。
- 风险标签使用对应风险色，见第 7 节。
- 标签数量过多时自动换行，不能横向溢出。

### 6.6 空状态

空状态必须包含：

- 简短标题，例如“暂无检测记录”。
- 一句可执行说明，例如“提交第一条新闻后，检测结果会保存在这里。”
- 一个主行动按钮，例如“去检测新闻”。

不允许出现大片空白区域。

### 6.7 加载状态

- 接口超过 300ms 必须显示 skeleton、spinner 或进度状态。
- 结果页加载使用首屏骨架：总分区域、三项分数卡、证据列表骨架。
- 检测过程中可展示 AI 分析步骤的逐步状态，但动画必须克制。

## 7. 风险等级视觉规范

| 分数范围 | 等级 | 主色 | 浅底 | 文案语气 |
|---|---|---|---|---|
| 80-100 | 可信新闻 | `#16A34A` | `#DCFCE7` | 可信、低风险 |
| 60-79 | 存疑信息 | `#D97706` | `#FEF3C7` | 建议核查 |
| 40-59 | 疑似谣言 | `#F97316` | `#FFEDD5` | 谨慎传播 |
| 0-39 | 高风险谣言 | `#DC2626` | `#FEE2E2` | 高风险、勿转发 |

展示规则：

- RiskTag 由颜色块、文字、状态图标组成。
- 高风险谣言必须在结果页首屏有明显红色风险提示条，但不使用闪烁动画。
- 分数仪表或环形图必须与等级颜色同步。
- 色盲可访问性：同时使用文字、图标、边框或警示条表达状态。

## 8. 检测结果页层级

检测结果页是答辩展示核心页面，必须按以下层级组织。

### 8.1 第一屏

第一屏必须突出：

1. `final_score`：使用 48px 左右大数字，旁边标明“综合可信度评分”。
2. `risk_level`：使用大号风险标签，与分数色彩一致。
3. 一句话判断结论：展示 `judgement_result` 或核心 `reason` 摘要。
4. 三项分数并列展示：`evidence_score`、`llm_score`、`rule_score` 三张等宽指标卡。
5. 主操作：下载 PDF 报告、返回检测、查看历史。

首屏布局建议：

- 左侧：最终评分、风险等级、判断摘要、操作按钮。
- 右侧：分数仪表或环形进度 + 三项分数概览。
- 下方露出“风险点/证据”区域的开头，方便截图体现页面完整度。

### 8.2 第二层：风险与解释

- 风险点：用警示列表或分组卡展示，不平铺长段文字。
- 关键词：使用标签云或分组标签，最多优先展示 12 个，多余折叠。
- 判断理由：用摘要卡展示，不超过 3-5 行，必要时展开。

### 8.3 第三层：证据与相似新闻

- 证据 Top10：使用 EvidenceList 卡片/表格混合展示，包含标题、来源、摘要、相似度、排名。
- 相似新闻：按风险等级标注，可与证据分为左右两栏或 tab。
- 相似度建议用进度条或小型条形表达，不只显示小数。

### 8.4 第四层：建议与 AI 分析过程

- 建议：使用浅蓝或浅黄信息面板，强调“下一步核查建议”。
- AI 分析过程：使用步骤条展示关键词提取、证据检索、LLM 分析、规则评分、报告生成。
- 免责声明：放在页面底部，语气克制，说明系统为辅助判断工具，不替代人工事实核查。

## 9. ECharts 规范

- 趋势数据：折线图或面积图，主线蓝色，填充透明度约 20%。
- 分类比较：柱状图/横向柱状图，按数值降序，显示数值标签。
- 分数构成：雷达图最多 3-5 个轴；本项目三项分数也可用并列 KPI 卡替代。
- 风险分布：环形图可以使用风险四色，但必须显示图例和 tooltip。
- 图表容器必须有固定高度，桌面常规 280-360px，避免加载后布局跳动。
- 图表不使用过度 3D、阴影、炫光和复杂渐变。

## 10. 页面开发规则

### 10.1 用户端页面

- 首页：第一屏要传达“智闻辨真”和可信度检测能力，不做纯营销空页；必须有立即检测入口。
- 登录注册：保持安全产品气质，表单清晰，错误状态明确。
- 新闻检测：输入体验优先，标题和正文区域权重最高，示例新闻入口可作为辅助。
- 检测结果：严格遵守第 8 节层级。
- 历史记录：表格清爽，支持风险筛选、时间、标题、分数、详情入口。
- 高风险新闻：强调公开案例展示、关键词和风险等级，不制造恐慌。
- 个人中心：账户信息、检测统计、最近记录，保持轻量。

### 10.2 Vue 与 Element Plus

- Element Plus 只作为基础交互能力，不直接裸露默认视觉。
- 统一封装或复用：RiskTag、ScoreCard、EvidenceList、AgentSteps、PageHeader。
- 页面请求统一走 `src/api`，状态统一由 Pinia 管理。
- Vue 模板使用语义元素：`main`、`section`、`nav`、`button`，不使用 `div` 伪按钮。
- 所有路由页面必须有 loading、empty、error 三类状态。

### 10.3 可访问性与响应式

- 文本对比度至少达到 WCAG AA。
- 键盘 focus-visible 必须可见。
- 表单 input 必须有 label。
- 不以颜色作为唯一状态表达。
- 375px 宽度不得横向滚动；表格在移动端可改为卡片列表。

## 11. 禁止事项

1. 禁止生成默认 Element Plus 后台模板页面。
2. 禁止将检测结果字段从上到下平铺成普通文字。
3. 禁止大面积纯白空页面。
4. 禁止大面积渐变背景、发光球、装饰性 blob。
5. 禁止使用 emoji 当图标。
6. 禁止文本溢出按钮、卡片、标签或表格单元格。
7. 禁止为了炫技加入过度动画、3D、复杂背景。
8. 禁止随意改变 API 字段名和路由约定。

## 12. 后续落地顺序建议

1. 建立全局样式变量和基础布局。
2. 先做通用组件：RiskTag、ScoreCard、PageHeader、EvidenceList、AgentSteps。
3. 开发用户端页面骨架和路由。
4. 优先打磨检测结果页。
5. 接入接口与 loading/empty/error 状态。
6. 最后做响应式、截图级视觉复核和浏览器验证。
