# 01 项目总体设计文档

# 智闻辨真：基于 RAG 与大语言模型的新闻可信度评估系统

> 本文档用于说明项目的整体定位、系统目标、用户角色、核心业务流程、技术架构和功能边界。  
> 后续使用 Codex 辅助开发时，需先让 Codex 阅读本文档，再根据数据库设计、接口设计和开发任务清单逐步实现代码。

## 1. 项目背景

随着网络新闻、社交媒体内容和短视频文案的快速传播，未经核实的信息、标题党内容、夸大表达和谣言信息更容易在互联网上扩散。传统人工审核方式效率较低，普通用户也很难快速判断一条新闻是否可信。

本项目围绕课程综合设计参考题目中的“基于大语言模型的网络新闻真伪鉴别系统设计”展开，进一步升级为一个面向求职展示的大模型应用项目：**智闻辨真：基于 RAG 与大语言模型的新闻可信度评估系统**。

系统不简单做“真 / 假”二分类，而是采用“可信度评估 + 谣言风险识别 + 证据检索 + 可解释报告”的设计思路，通过 RAG 技术从新闻知识库中召回相关证据，再结合 DeepSeek 大模型进行分析，最终输出可信度评分、风险等级、判断理由、风险点、关键词、相似新闻、辟谣建议和 PDF 检测报告。

## 3. 项目定位

本项目是一个面向网络新闻内容的 AI 应用系统，主要用于辅助用户判断新闻内容的可信程度和谣言风险。

项目定位不是“绝对判定新闻真假”，而是：

- 对新闻进行可信度评估；
- 对可能存在谣言风险的内容进行提示；
- 给出可解释的判断理由；
- 展示检索到的证据和相似新闻；
- 生成结构化检测报告；
- 为管理员提供知识库维护、Prompt 管理和风险数据统计能力。

### 5.1 前端技术栈

- ECharts

### 5.2 后端技术栈

- Python
- FastAPI
- SQLAlchemy
- Pydantic
- JWT
- Uvicorn

### 5.3 数据库与存储

- MySQL：保存用户、知识库、检测记录、报告、Prompt、日志等业务数据
- Chroma：保存知识库文本向量，用于相似新闻和证据检索
- 本地文件存储：保存生成的 HTML / PDF 报告

### 5.4 大模型与 AI 能力

- DeepSeek API：用于可信度分析、风险点提取、关键词提取和辟谣建议生成
- Embedding 模型：用于将新闻文本和知识库文本转为向量
- RAG：用于根据用户输入新闻召回相关证据，再增强大模型判断
- 轻量 Agent：用于组织“关键词提取、证据检索、风险分析、报告生成”等步骤

## 7. 系统核心业务流程

用户输入新闻后，系统执行如下流程：

```text
用户输入新闻标题和正文
        ↓
文本预处理
        ↓
关键词提取
        ↓
轻量 Agent 调度任务
        ↓
Chroma 向量检索相似新闻和辟谣证据
        ↓
构造 RAG Prompt
        ↓
调用 DeepSeek 大模型进行可信度分析
        ↓
执行风险规则评分
        ↓
计算最终可信度评分
        ↓
生成风险等级、判断理由、风险点、证据、建议
        ↓
保存检测记录
        ↓
生成 HTML 报告和 PDF 报告
        ↓
前端展示检测结果
```

## 8. RAG 检测流程设计

### 8.1 知识库构建

知识库中的每条数据建议包含：

- 新闻标题；
- 新闻正文；
- 新闻类别；
- 真实性标签；
- 来源名称；
- 来源链接；
- 发布时间；
- 新闻摘要；
- 关键词；
- 辟谣说明；
- 风险等级；
- 管理员备注。

### 8.2 入库流程

```text
管理员新增新闻知识库数据
        ↓
后端清洗标题、正文、摘要、关键词
        ↓
调用 Embedding 模型生成向量
        ↓
原始数据存入 MySQL
        ↓
向量数据写入 Chroma
```

### 8.3 检索流程

```text
用户输入新闻标题 + 正文
        ↓
后端合并为检索文本
        ↓
生成查询向量
        ↓
在 Chroma 中检索 Top10 相似证据
        ↓
页面展示 Top10 证据
        ↓
选取 Top5 证据构造 Prompt
        ↓
调用 DeepSeek 进行分析
```

### 8.4 Top-K 设计

课程阶段采用固定配置：

- Chroma 检索 Top10；
- 前端页面展示 Top10；
- Prompt 中使用 Top5 核心证据；
- 后续增强版可以支持后台配置 Top-K 参数。

## 10. 可信度评分设计

系统最终可信度由三部分组成：

```text
最终可信度 = 检索证据相关度评分 × 40%
          + 大模型判断评分 × 40%
          + 来源 / 风险规则评分 × 20%
```

---

### 10.1 检索证据相关度评分

根据 Chroma 返回的 Top5 证据相似度计算。

建议公式：

```text
证据相关度评分 = Top5 相似度平均值 × 100
```

如果向量数据库返回的是距离值，则需要转换为相似度后再计算。

---

### 10.2 大模型判断评分

DeepSeek 根据输入新闻和检索证据返回 0-100 分。

要求模型返回结构化 JSON：

```json
{
  "llm_score": 72,
  "risk_level": "存疑信息",
  "reason": "该新闻部分内容缺少明确来源，且与知识库中相似事件存在表述差异。",
  "risk_points": ["来源不明确", "标题存在夸张表达"],
  "keywords": ["网络传言", "官方回应", "风险提示"],
  "suggestion": "建议进一步核查权威媒体或官方通报。"
}
```

---

### 10.3 来源 / 风险规则评分

规则评分主要检查：

- 是否包含夸张词；
- 是否缺少明确来源；
- 是否包含强情绪化表达；
- 是否包含绝对化表述；
- 是否与知识库证据冲突。

常见风险词示例：

```text
震惊、疯传、惊天秘密、紧急扩散、必看、内幕、百分百、绝对、所有人、一定
```

## 11. 风险等级设计

最终输出采用四级风险等级：

| 分数范围 | 风险等级 |
|---|---|
| 80-100 | 可信新闻 |
| 60-79 | 存疑信息 |
| 40-59 | 疑似谣言 |
| 0-39 | 高风险谣言 |

系统需要强调：本系统是辅助判断工具，不替代人工事实核查。

免责声明需要出现在：

- 检测结果页；
- PDF 检测报告；
- 课程设计报告。

## 19. 项目最终总结

