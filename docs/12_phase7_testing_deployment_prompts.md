> 角色分工：ChatGPT 负责项目规划、需求拆解、技术方案、Prompt 设计、代码审查意见；Codex 负责辅助编码、修复 Bug、补接口、补页面和生成测试。

# 第七阶段：联调测试、部署准备与课程答辩材料开发方案

## 一、阶段目标

第七阶段目标是完成系统收尾工作，包括前后端联调、Bug 修复、接口稳定性检查、测试数据准备、README 编写、部署说明、课程报告截图清单和答辩演示流程。

这一阶段不要再大规模新增功能，重点是稳定、完整、可演示。

## 二、技术方案

### 2.1 联调范围

必须完整跑通以下路径：

```text
注册
→ 登录
→ 新闻检测
→ 检测结果页
→ 生成并下载 PDF 报告
→ 查看历史记录
→ 管理员登录
→ 查看后台统计
→ 管理知识库
→ 管理 Prompt 模板
→ 查看高风险新闻
```

### 2.2 测试数据准备

至少准备：

```text
30 条知识库演示数据
5 条可信新闻
5 条存疑信息
5 条疑似谣言
5 条高风险谣言
2 个普通用户账号
1 个管理员账号
5 条适合答辩演示的检测输入
```

后续可以扩展到 100 条知识库数据。

### 2.3 不建议本阶段新增的内容

本阶段不要再做：

- 多模型切换；
- 联网搜索；
- 多模态图片检测；
- 复杂 Agent 框架；
- 大规模重构；
- 更换前端框架；
- 更换数据库。

## 四、本阶段开发提示词 2：生成测试数据与初始化脚本

```text
请为项目生成演示测试数据和初始化脚本。

要求：
1. 生成 30 条知识库演示数据；
2. 数据包含可信新闻、存疑信息、疑似谣言、高风险谣言；
3. 每条数据包含 title、content、category、truth_label、source_name、publish_time、summary、keywords、debunking_explanation、risk_level；

5. 生成 2 个普通用户账号；
6. 提供 seed 脚本，例如 scripts/seed_data.py；

8. 不要覆盖已有真实数据，除非明确使用 reset 参数。

完成后请说明：
1. 如何运行初始化脚本；
2. 默认账号密码；
3. 如何验证数据写入成功；
4. 如何验证 Chroma 向量生成成功。
```

## 九、本阶段开发提示词 7：生成答辩演示脚本

```text
请为“智闻辨真：基于 RAG 与大语言模型的新闻可信度评估系统”生成课程答辩演示脚本。

演示路径：
登录系统
→ 输入新闻
→ 系统检索证据
→ DeepSeek 生成分析
→ 展示可信度评分和风险等级
→ 展示风险点、关键词、相似新闻
→ 下载检测报告
→ 查看历史记录
→ 查看后台数据可视化

5. 控制在 3-5 分钟内。
```
