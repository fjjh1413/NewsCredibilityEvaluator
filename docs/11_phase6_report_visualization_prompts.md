# 第六阶段：PDF 报告生成、数据可视化与高风险展示开发方案

## 一、阶段目标

第六阶段目标是提升系统演示效果和课程设计完整度。核心包括 PDF 检测报告生成、用户端报告下载、后台数据可视化、高风险新闻展示和统计接口完善。

这一阶段是答辩展示的加分阶段，也是把系统从“能用”变成“好展示”的关键阶段。

## 二、技术方案

### 2.1 报告生成方案

推荐流程：

```text
检测记录详情
        ↓
后端读取检测记录、证据匹配、风险点、建议
        ↓
使用 HTML 模板生成报告页面
        ↓
将 HTML 转换为 PDF
        ↓
保存 PDF 路径到 reports 表
        ↓
前端提供下载按钮
```

### 2.2 PDF 报告内容

报告包含：

1. 报告标题；
2. 检测新闻标题；
3. 检测时间；
4. 可信度评分；
5. 风险等级；
6. 判断结论；
7. AI 分析理由；
8. 风险点列表；
9. 关键词；
10. 检索证据；
11. 相似新闻；
12. 辟谣建议；
13. 免责声明。

### 2.3 数据可视化指标

后台统计页应展示：

- 总检测次数；
- 今日检测次数；
- 风险等级分布；
- 新闻类别分布；
- 近 7 日或近 30 日检测趋势；
- 高频关键词；
- 高风险占比；
- 用户活跃度；
- 知识库数量统计。

## 三、本阶段开发提示词 1：实现 PDF 报告生成后端

```text
你现在负责开发“智闻辨真”项目第六阶段的 PDF 检测报告生成功能。请先阅读 docs/01_project_design.md、docs/02_database_design.md、docs/03_api_design.md。

本次任务只实现后端报告生成，不修改前端页面。

要求：
1. 创建 reports 表对应 Model 和 Schema；
2. 新建 services/report_service.py；
3. 根据 detection_id 读取检测记录、证据匹配、用户信息；
4. 使用 HTML 模板生成检测报告内容；
5. 将 HTML 转换为 PDF；
6. 保存 html_path、pdf_path 到 reports 表；
7. 实现 POST /api/report/generate/{detection_id}；
8. 实现 GET /api/report/download/{report_id}；
9. 普通用户只能生成和下载自己的报告；
10. 管理员可以下载全部报告。

报告必须包含：
新闻标题、检测时间、可信度评分、风险等级、判断结论、AI 分析理由、风险点、关键词、检索证据、相似新闻、辟谣建议、免责声明。

注意：
- 不要把 PDF 文件保存到代码目录；
- 报告保存目录从环境变量读取，例如 REPORT_DIR；
- 如果 PDF 生成失败，要返回明确错误；
- 不要重新调用 DeepSeek，报告内容来自已有检测记录。

完成后请说明：
1. PDF 生成依赖；
2. 报告保存路径；
3. 接口调用方式；
4. 如何测试下载；
5. 常见失败原因。
```

## 五、本阶段开发提示词 3：实现后台统计接口

```text

5. GET /api/admin/statistics/keywords

- overview 返回总检测次数、今日检测次数、用户总数、知识库数量、高风险数量、报告数量；

- category-distribution 返回新闻类别数量；

- user-activity 返回用户检测活跃度；
- knowledge-overview 返回知识库类别和标签统计；
- 所有接口仅 admin 可访问；
- 数据来自 MySQL，不要写死。

完成后请给出每个接口的示例响应。
```
